# To do 13: Cancel a running download (medium): "Do we have a way to cancel a video currently in download?"

- **Goal:** stop a running download without closing the window. Now the only way is to close it, which also loses the choices made (decided in To do 3 to keep the first version small). Example: a long YouTube video started at Best when 720p was meant: click Cancel, the window says so, the half-downloaded files are gone, and the next download can start. It matters more once To do 8 is built: a channel link can mean hundreds of videos.
- **Read first:** `download()` in downloader.py with its hooks `on_progress` and `on_step` and `there_before`; `App.start_download`, `check_events`, `update_states` and `on_destroy` in app.py; docs/decisions.md To do 3 ("one download at a time, no Cancel button; closing the window stops it"); docs/research/yt-dlp-library.md (what yt-dlp reports while downloading and while ffmpeg works).
- **Approach** (an idea, nothing tested yet):
  - A Cancel button next to Download, usable only during a download.
  - The window sets a flag (a `threading.Event`) that `download()` gets; the progress hook raises an error when it is set, so yt-dlp stops at its next progress report (several a second while downloading). yt-dlp has no stop call of its own (to check in the build).
  - While ffmpeg joins video and audio or converts to MP3 there are no progress reports, so Cancel would only take effect when that part ends (seconds on a long video). Research whether that step can be stopped too; otherwise the window says it stops after this step.
  - The window says "Cancelled." in the normal color (a new event, or a plain message), and the choices stay as they were.
  - Clean up only what this download made and didn't finish (`.part`, `.ytdl`, fragment files, a half-joined file); never a file that was there before (`there_before`). This deletes files in the user's folder: build with Opus, review at high effort.
- **Ask the user:** (a) a separate Cancel button, or Download turning into Cancel during a download? Suggested: a separate button next to Download, greyed out when nothing is downloading. (b) delete the half-downloaded files? Suggested: yes, only files this download made that aren't finished. (c) with playlists (To do 8), Cancel stops the rest and keeps the videos already finished? Suggested: yes. (d) Escape cancels too? Suggested: no, a key that cancels by accident is worse than a click.
- **Test:** Claude: a downloader test with the local web server (cancel partway: no `.part` left, a file from before untouched, the cancel reported); app tests with the fake download; a GUI test step that clicks Cancel. User: start a long YouTube video, click Cancel partway: the window says Cancelled, nothing half-downloaded is left in Downloads\Videos, and the next download works.
