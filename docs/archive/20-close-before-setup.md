# To do 20: Setup and the uninstaller ask to close an open window first (small)

Raised by Claude in To do 11, step B (2026-11-14), from a measurement; the user hasn't seen it happen. Not "bugs me": build it when one of the cases below actually happens.

- **Problem:** Setup and the uninstaller don't wait for an open Video Downloader window (docs/research/installer.md, "The installer"):
  - Uninstalling with the window open (measured): exit code 0, but 44 files stay in `%LOCALAPPDATA%\Programs\Video Downloader` (the running .exe and the libraries it loaded), the window keeps running, and a normal uninstall says some elements couldn't be removed.
  - Installing over an open window (not tried): Setup offers to close it (`CloseApplications`). With "Do not close", `[InstallDelete]` has already removed the unlocked files from `_internal`, and the locked ones block the copy, so the app can end up a mix of old and new files.
  - Setup closing the window (not tried) stops a running download the way closing the window does (the half-downloaded file stays), with no question asked in a silent install.
- **Goal:** with the window open, Setup and the uninstaller say "close Video Downloader first" (with OK/Cancel; Inno's box has no Retry, found while building) instead of going ahead.
- **Read first:** installer/setup.iss ([Setup]); app.py `start()` (where the taskbar ID is set, line ~988) and `main()` (where the pipe is taken); docs/research/installer.md "The installer"; Inno Setup's help on `AppMutex`.
- **Approach:** Inno's standard way: the window holds a named mutex for as long as it runs (`ctypes.windll.kernel32.CreateMutexW(None, False, NAME)`, handle kept until the process ends, about 6 lines in app.py), and setup.iss gets `AppMutex=NAME` (Setup also checks it when it starts, and the uninstaller does too). A test checks that setup.iss names the same mutex as app.py, like the other shared names (tests/test_installer.py).
- **Ask the user:** (a) the mutex's name: suggested `VideoDownloader.App`, the taskbar ID. (b) the project's own window (`python -m video_downloader`) holds it too, so Setup also waits for that one: suggested yes (they share the one window anyway). (c) keep `CloseApplications=yes` for anything else using the files (the Chrome helper for a moment): suggested yes.
- **Test:** Claude: the silent round trip with the window open: the uninstaller stops, the files and the window stay as they are; with the window closed it goes through as before. User: open the installed window, start the uninstall from Settings > Apps: it asks to close Video Downloader first; close it, click OK, and it uninstalls completely. The same for running Setup over an open window.
