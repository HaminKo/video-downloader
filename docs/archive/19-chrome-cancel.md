# To do 19: Cancel from the Chrome popup (medium): "I notice there isn't a way to cancel from the chrome extension"

- **Problem:** the Chrome popup can start a download but not stop it. To cancel, you open the window (its taskbar button, the blue arrow since To do 18), select the row and press Cancel. To do 16 left Cancel out on purpose, as part of "everything in Chrome" (progress, the queue, Cancel: docs/decisions.md, 2026-11-14); this to-do is Cancel alone.
- **Goal:** on a video's page, the popup's Cancel stops that video's download in the window, or takes it off the list if it's still waiting, and says so. Example: Download on a long YouTube video, open the popup again on the same tab, Cancel: the popup says "Cancelled." and the window's row says Cancelled, with the half-downloaded files deleted as with the window's own Cancel.
- **Read first:** extension/popup.js `send()` and `problemSending()`, extension/popup.html; host.py `answer()`; handoff.py `Listening.serve()`, `send()`, `checked_message()`; app.py `cancel_download()`, `remove_selected()`, `check_links()`; tests/gui/popup_gui.py and fake_chrome.js; docs/archive/16-chrome-popup.md (the popup's design, and why "everything in Chrome" was rejected).
- **Approach (suggested; the build session checks it):** a new message `{"cancel": LINK}` from the popup through the helper to the window. Links go one way today: `send()` only writes and the window closes the connection before it reads the message. For the popup to say what happened, the window answers on the same connection: the listener thread hands the message to the Tk thread and waits (with a time limit) for its answer, e.g. `"cancelled"`, `"removed"` or `"not in the list"`. The window finds the row by the link exactly as it was added (the popup sends the same tab link both times), and reuses `cancel_download()` for the running row and Remove's code for a waiting one. With no window open, the helper opens nothing and replies "Video Downloader isn't open.".
- **Ask the user:** (a) cancel this tab's video only, or whatever is downloading now? Suggested: this tab's video (it can't stop the wrong one). (b) Cancel always shown in the popup, or only when the window has this tab's video? Suggested: always shown; knowing beforehand needs a round trip to the window each time the popup opens. (c) A waiting video: take it off the list (as Remove does), or keep it as a Cancelled row? Suggested: keep it as Cancelled, so the window shows what happened. (d) Two windows open (until To do 17): only the one that listens gets the Cancel. Fine for now? Suggested: yes.
- **Test:** Claude: handoff tests for the new message and its answer (and a window that doesn't answer in time); app tests for cancelling the running row, a waiting row and a link not in the list; host tests for the replies and "isn't open" (no window started); popup GUI test cases for Cancel and each reply, plus a screenshot. User: Download a long video from the popup, then Cancel from the popup on the same tab; Cancel on a page that isn't in the list; Cancel with the app closed.
