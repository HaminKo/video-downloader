# To do 14: An MP3 download must not delete the MP4 already there (small): "add it as To do 14, built next"

- **Problem:** an MP3 download deletes an MP4 of the same video that was already in the folder, on sites that have no separate audio file. Found while building To do 13 (measured 2026-11-12 with the test clip: MP4 download, then MP3 into the same folder; afterwards only `clip.mp3` was left). The user hasn't seen it happen. Why (read in yt-dlp's source): the MP3 preset's format `ba[acodec^=mp3]/ba/b` falls back to `b`, the file with video and sound, named `Title.mp4`; yt-dlp finds that name "already downloaded", converts it to MP3, and then deletes it as the conversion's original (`FFmpegExtractAudioPP` returns it, `run_pp` deletes it unless `keepvideo` is set). On YouTube the audio is a file of its own (`Title.m4a` or `Title.webm`), so it shouldn't happen there (not measured).
- **Goal:** after an MP3 download, an MP4 that was there before is still there, unchanged. Example: download a clip as MP4, then the same clip as MP3: both files are in Downloads\Videos.
- **Read first:** docs/research/yt-dlp-library.md "Files yt-dlp deletes" and "Cancelling"; `PRESETS[Kind.MP3]`, `options()` and `download()` (`there_before`, `remove_unfinished()`) in downloader.py; docs/decisions.md "MP4 that plays everywhere ... `-t mp4` and `-t mp3` presets" and "A Cancel button ... deletes only the new files named after its video".
- **Approach** (an idea, nothing tested yet): set `keepvideo: True` for MP3, so yt-dlp deletes nothing, and delete the downloaded original ourselves only when it wasn't in the folder before (`there_before`), like the Cancel clean-up. Its path: the hooks (ExtractAudio's `info_dict["filepath"]` before conversion, or the progress report's `filename`). Alternatives to weigh in the build: another file name for MP3's download (a suffix, then the MP3 named without it), or yt-dlp's `paths: {"temp": ...}`. Check that MP3 "already there" (`Title.mp3`) still works and that a converted MP3 still leaves only `Title.mp3` behind.
- **Ask the user:** (a) when the MP4 is there, may the MP3 be made from it instead of downloading again (yt-dlp does that now, and it's faster)? Suggested: yes. (b) also check on YouTube in the test (MP4, then MP3 of the same video)? Suggested: yes, one video.
- **Test:** Claude: downloader tests with the local web server: MP4 then MP3 into the same folder leaves both, the MP4 unchanged; MP3 alone leaves only `Title.mp3`; MP3 twice says "already there". User: a YouTube video as MP4, then as MP3: both files are in Downloads\Videos and the MP4 still plays.
