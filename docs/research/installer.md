# An .exe and an installer (To do 11)

Started 2026-11-14 (To do 11, questions and plan). Marked by how each fact is known: read (in code or docs), measured (run on this PC), or general knowledge (not checked).

## The two parts
- **The app as an .exe:** a bundler packs Python, tkinter, yt-dlp and the app into a folder with `Video Downloader.exe`, started by double-click, no console window. PyInstaller is the usual one; yt-dlp's own `yt-dlp.exe` is built with it (general knowledge).
- **The installer:** a `Setup.exe`, run once, that copies that folder into the user's programs folder and adds a Start-menu entry and an entry in Settings > Apps to uninstall. Inno Setup is the usual free one for this (general knowledge).
- **One-file vs. one-folder:** PyInstaller's one-file .exe unpacks itself into a temp folder at every start (slower start, more antivirus false alarms); the one-folder build starts straight away. With an installer the folder is hidden anyway (general knowledge, start times not measured).

## What the bundle needs
- **yt-dlp ships its own PyInstaller hook** (read 2026-11-14 in the `.venv`, yt-dlp 2026.10.26: `yt_dlp/__pyinstaller/hook-yt_dlp.py`): it adds yt-dlp's lazily imported modules, websockets, requests, urllib3, mutagen, brotli, certifi and pycryptodomex, and `collect_data_files('yt_dlp_ejs', includes=['**/*.js'])`, so the JavaScript files YouTube needs (with Deno) go into the bundle without settings of our own.
- **The icons:** `app.ICONS` and `browser.EXTENSION_FOLDER` are found from `__file__` (read). In a built app they need a path from the .exe's folder (`sys.frozen`, `sys.executable`), with the extension folder copied next to the .exe.
- **The Chrome helper:** today `host.bat` runs `python -m video_downloader.host`, and `host.start_window` starts `pythonw.exe -m video_downloader` (read). In a built app both need .exe files of their own: the helper must use stdin and stdout, so it is a console .exe; Chrome starts an `.exe` directly and hidden, anything else through `cmd.exe` (docs/research/browser-button.md, read in Chromium's code 2026-11-13). The host manifest's `path` may be relative to the manifest's folder on Windows (same file, from Chrome's docs), so a `host.json` next to the helper .exe needs no path written at install time.

## The build (step A, measured 2026-11-14)
- **Tools:** PyInstaller 6.22.3 (pyinstaller-hooks-contrib 2026.10) in the `.venv`, Python 3.13.1, yt-dlp 2026.10.26.
- **Two .exe files in one folder:** a spec file with two `Analysis` and two `EXE` (`exclude_binaries=True`) and one `COLLECT` gives `Video Downloader.exe` (11.4 MB, no console) and `chrome-helper.exe` (2.2 MB, console) sharing one `_internal` folder. Each .exe holds its own module archive: the helper's has neither yt-dlp nor tkinter (checked in `build/pyinstaller/video-downloader/PYZ-01.toc`); the app's has yt-dlp's extractors (`yt_dlp.extractor._extractors`, `youtube`, `reddit`) and `yt_dlp_ejs`, whose two `.js` files are in `_internal/yt_dlp_ejs/yt/solver/`.
- **Entry scripts:** `installer/start_app.py` and `start_helper.py` import `main` and call it. They are plain imports so PyInstaller follows them (`runpy` would hide the module from it), and they keep `src/video_downloader/` off PyInstaller's search path, where the package's modules would also count as top-level ones.
- **Size and time:** `python installer/build.py --no-update` took 73 s the first time and 28 s the second; the folder is 43 MB. It includes `setuptools` (pulled in by some dependency; not looked into). Two harmless warnings: urllib3's emscripten part (browser-only) and curl_cffi (not installed).
- **The helper:** one message (`{"link": "chrome://extensions"}`, which never reaches the pipe) got `{"ok": false, "error": "Only web pages can be sent."}` back, nothing else on stdout or stderr; 0.84 s the first time (a new .exe, likely Defender scanning it: not checked), then 0.08 s.
- **The window:** `Video Downloader.exe` showed its window after 2.96 s the first time and 0.47 s the second, and closed on `WM_CLOSE` with exit code 0. No antivirus warning.
- **build.py imports only `places`:** importing the app would load yt-dlp's compiled parts (`_brotli`, `Cryptodome`; seen loaded by the review), and on Windows pip can't replace a `.pyd` a running program has open, so the yt-dlp update could fail when one of them has a new release (the review's finding, from general knowledge; not reproduced). The icon sizes come from the PNGs' names instead of `app.ICON_SIZES`.
- **Not checked by Claude:** a real download from the built app (it would save into the user's Videos folder and history); the user's hand test does that.

## The installer (step B, measured 2026-11-14)
- **Inno Setup on this PC:** 6.7.3 (winget `JRSoftware.InnoSetup`), installed into another project's folder (docs/local.md), not on PATH and not in the standard folders. Its own uninstall entry, `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Inno Setup 6_is1`, names the folder in `InstallLocation`; build.py reads that (this user, then all users, both registry views), then looks on PATH.
- **The recipe:** `installer/setup.iss`. The names shared with the Python code are `#define` lines that tests/test_installer.py checks; the version is the build's date and time (`GetDateTimeString`; the round trip below ran with the date only). build.py writes `host.json` into the built folder first (`browser.write_manifest()`, path `chrome-helper.exe`, relative), so Setup only copies it and writes Chrome's key.
- **Size and time:** `ISCC.exe /Q installer\setup.iss` took 12 s; Setup.exe is 22 MB (lzma2, solid) for the 43 MB folder. The whole `python installer/build.py --no-update` took 2 min 6 s this time, so PyInstaller about 110 s (28 to 73 s in step A; not looked into).
- **Silent install** (`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`): 5.6 s. Into `%LOCALAPPDATA%\Programs\Video Downloader`: the two .exe files, `_internal`, `extension`, `host.json`, `unins000.exe` and `unins000.dat`. Chrome's key held `...\Video Downloader\host.json`. The Start-menu shortcut (`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Video Downloader.lnk`) pointed at `Video Downloader.exe` with `System.AppUserModel.ID` = `VideoDownloader.App` (read with `Shell.Application`'s `ExtendedProperty`). No desktop shortcut (unticked). Settings > Apps entry: "Video Downloader", version 2026.11.14, 45,812 KB.
- **The installed app:** the helper answered the `chrome://` message with "Only web pages can be sent." (0.92 s the first time); the window showed after 3.17 s and closed on `WM_CLOSE` with exit code 0.
- **Silent uninstall with the window closed:** exit code 0; the folder, Chrome's key, the shortcut and the Settings entry were gone, and `%APPDATA%\video-downloader` was unchanged (same files, sizes and times).
- **Installing over an install** (after the review, with the window closed): a file put into the installed `_internal` and one into `extension` were gone after the second Setup (`[InstallDelete]`), the rest was there, Settings > Apps had one entry with version "2026.11.14 18:42", and the helper (0.83 s) and the window (2.85 s) worked.
- **Uninstall with the window open:** exit code 0, but 44 files stayed (the running `Video Downloader.exe` and the libraries it had loaded; the folders failed with error 145, not empty), the window kept running, and the log ended "Removed all? No". Chrome's key and the shortcut were removed. The uninstaller didn't try to close the window (no Restart Manager lines in its log, where Setup has `CloseApplications`). A normal (not silent) uninstall then shows that some elements couldn't be removed (general knowledge; the run was silent). Inno's way to stop this is `AppMutex`: the app holds a named mutex, and Setup and the uninstaller ask to close it first (general knowledge, not built). Replaced by To do 20: the uninstaller now stops instead (below, "The window open").
- **Not checked by Claude:** Setup's pages by hand, installing over an open window (silently since: below), Chrome reaching the installed helper through the relative path, and a pinned taskbar button (the user's test).

## The window open (To do 20, 2026-11-14)
- **How:** `main()` calls `hold_mutex(APP_ID)` just before `start()` (not when it hands over to an open window): `CreateMutexW(None, False, "VideoDownloader.App")`, the taskbar ID, never closed; setup.iss has `AppMutex={#TaskbarId}`. First built into `start()`; the review moved it, as every test and screenshot window then held it (one more handle each, until pytest ended) and the unit test passed whatever `start()` did once an earlier test had built a window. Inno's help ("[Setup]: AppMutex", read in Inno Setup 6.7.3's ISetup.chm): Setup and the uninstaller check for it "at startup"; the app needn't close it, Windows does when the process ends; names are case sensitive; `Global\` is only for other sessions (not used: the app installs for one user).
- **The box** (read in Default.isl): "Setup has detected that Video Downloader is currently running. Please close all instances of it now, then click OK to continue, or Cancel to exit." (the uninstaller's starts "Uninstall has detected"). OK and Cancel, not Retry. The uninstaller checks in its second phase, the copy in TEMP started with `/SECONDPHASE` (read in its log), so likely after the first phase's "Are you sure?" (general knowledge).
- **Silent round trip** (measured twice, with the mutex in `start()` and then in `main()`, the same results; times from the second, `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG`): the installed window showed after 4.5 s and another process found the mutex (`OpenMutexW`). Uninstall with the window open: exit code 1 after 0.7 s, the log says "Defaulting to Cancel for suppressed message box (OK/Cancel): Uninstall has detected that Video Downloader is currently running"; every file (1026, same sizes and times), Chrome's key, the shortcut and the window stayed. Setup over the open window: exit code 1 after 0.7 s, the same in its log ("Setup has detected", then "Got EAbort exception"), nothing changed. After closing the window (no mutex left): Setup exit 0 (5.5 s), uninstall exit 0, "Removed all? Yes", the folder gone. `%APPDATA%\video-downloader` unchanged throughout. Installed again afterwards (Chrome's key points at it, as before the test); the helper answered in 0.92 s.
- **An empty app folder can stay** (measured): after the uninstall above, `%LOCALAPPDATA%\Programs\Video Downloader` stayed, empty; again after a second install and uninstall. Removing the empty folder first, then install and uninstall: the folder was gone. So Inno removes the app folder only when its own install created it (read in the logs: no "Deleting directory" for the folder itself; general knowledge for the rule). Here the folder was older than the install log, likely from To do 11's uninstall with the window open, which left 44 files (not checked). Not to do with the mutex.

## Updating yt-dlp
- Inside a built app, `pip install -U` can't update yt-dlp (general knowledge). Options: build and install again with a newer yt-dlp, or the app fetches a newer yt-dlp itself at start-up (docs/decisions.md, 2026-11-11 Reddit entry: "about once a week, if it's ever wanted").

## Signing
- An unsigned `Setup.exe` downloaded from the internet gets SmartScreen's "Windows protected your PC". A file built on this PC carries no download mark, so SmartScreen shouldn't ask (general knowledge, not tested).
